1. Какие события активируют пайплайн?
Пайплайн запускается благодаря блоку on: в YAML-файле, Push — когда разработчик отправляет новые коммиты в определенные ветки.
Pull Request — когда создается или обновляется запрос на слияние в эти же ветки.

2. Будет ли пайплайн с тестами запускаться заново, если разработчик изменил только файл README.md или документацию?
В текущей конфигурации — да, запустится. GitHub Actions по умолчанию реагирует на любые изменения в файлах.

3. Как и где в конфигурационном файле GitHub Actions (YAML) вы указываете установку зависимостей для прогона тестов?
Это делается внутри блока jobs -> steps. Там есть шаги с ключевым словом run.
В Python мы писали команду: pip install -r requirements.txt.
В Java зависимости вообще не нужно устанавливать отдельной командой — Maven делает это автоматически, когда мы запускаем шаг он сам читает файл pom.xml и скачивает нужные библиотеки.

5. Всегда ли есть необходимость 100%-ого покрытия тестами?
Нет, не всегда.
В реальной коммерческой разработке 100% покрытие часто считается избыточным: это очень дорого по времени, а тестировать простые геттеры/сеттеры нет смысла. Обычно в компаниях требуют покрывать 70–80% самого важного бизнес-кода, чтобы поймать критичные баги.

6. Какой стек технологий и фреймворк автоматизации используется?

Контроль версий и CI: Git, GitHub, GitHub Actions.
Стек Python: фреймворк тестирования pytest, библиотека оценки покрытия coverage.
Стек Java: система сборки Maven, фреймворк тестирования JUnit 5, плагин для оценки покрытия JaCoCo.
